# 微信多开 WeChatMulti

Windows 上让多个微信号同时在线的小工具。

**用原版微信客户端，把每个号的资料隔离开 —— 不用反复扫码，多个号一起挂着。**

> 版本 0.1.1 ｜ 平台 Windows 10 / 11 ｜ 免费、开源、不收集任何数据
>
> **下载就能用**，不需要装 Python、不需要装依赖、不需要跑任何脚本：
>
> | 形态 | 文件 | 怎么用 |
> |---|---|---|
> | **绿色版**（推荐） | `WeChatMulti-v0.1.1-win64.zip` | 解压到任意位置 → 双击 `微信多开安装器.exe` |

> 到 [Releases](../../releases) 下载。

## 它解决什么问题

微信 4.x 同一台电脑上只允许一个实例。想用第二个号，只有三条路：

| 做法 | 体验 |
|---|---|
| 卸载重装、反复切换 | 每次都要扫码，聊天记录来回搬 |
| 用第三方「多开」软件 | 来源不明，聊天记录在别人手里 |
| **本工具** | 隔离资料目录，多个号同时在线，各跑各的 |

---

## 它做了什么

**核心只有一件事：把每个号的「资料」隔离开。**

微信把「我是谁」「我的聊天记录在哪」都存在用户目录下。同一台机器上，
如果所有实例共用同一份目录，第二个实例一启动就会被判定成「重复运行」。

本工具给每个实例准备**完全独立的一套目录**：

| 隔离的东西 | 具体路径 |
|---|---|
| 用户目录（`USERPROFILE`） | `<安装目录>\<代号>\Profile\` |
| 配置 | `<代号>\Profile\AppData\Roaming\Tencent\xwechat\` |
| 聊天记录 / 插件 / 图片 | `<安装目录>\Data\<代号>\` |

启动每个实例时，用一个启动脚本把 `USERPROFILE`、`APPDATA`、`LOCALAPPDATA`、
`TEMP` 全部指到它自己那套目录，再告诉微信「你的数据根在这里」。

**结果**：实例 A 和实例 B 在系统看来就是两个不同的用户，各自有独立配置、
独立聊天记录，可以同时登录、同时在线、同时收发消息。

**本工具不改微信的任何二进制文件** —— 用的是你自己电脑上装的那份原版官方微信，
复制一份到实例目录后启动。（早期版本用二进制补丁绕过单实例检查，
但测试发现新版本微信已经不需要了，见 [工作原理](#工作原理)。）

所以官方更新微信后本工具照常可用，不需要等我们发新版。

## 快速开始

### 第 1 步：装好官方微信

装 [微信 PC 版](https://windows.weixin.qq.com/)（4.x，本工具针对 4.x 设计）。
装完确认能正常登录主号。

### 第 2 步：装本工具

下载 `微信多开安装器.exe`，双击 → **选一个安装目录** → 完成。

> 目录要求：本地磁盘、**不要**放在 OneDrive 或网络盘、不要放在 U 盘。
> 微信会持续往里写数据，同步盘和移动盘会出问题。

### 第 3 步：加一个号

打开「微信多开管家」→ 点 **「新增实例」** → 选安装目录（默认记住上次）→ 完成。

### 第 4 步：开始用

每个实例在桌面上有一个启动图标，双击即可。首次启动会让你**扫码登录**，
之后这个号就长期在线了。

> **每个实例只能登录一个号**。要换号，删掉实例重新加一个。

## 功能一览

**实例管理**
- 新增 / 删除 / 启动实例，代号自动分配（A、B、C…）
- 每个实例独立窗口标题（`微信A` / `微信B`），方便在任务栏区分
- 独立数据根，随时整目录搬走或备份
- 实例清单（`instances.json`）明文存储，可手工编辑、可版本控制

**贴心的小工具**
- **防重复启动**：同实例已经在跑时，再点图标不会有第二个进程
- **窗口打标**：自动把窗口标题改成 `微信X`，不用自己改
- **数据根预置**：加实例时就把数据根写好，不留「首次启动再配置」的坑

**隐私**
- 全程离线，不联网
- 不收集使用数据、不写注册表、不装服务

## 工作原理

### 为什么不改二进制也能多开

早期版本（本工具的前身）需要给微信启动器打二进制补丁，绕过「本机只允许一个实例」
的检查。补丁点是三个跳转，绑死在特定微信版本上，官方一更新就失效。

实测（2026-10-30，微信 4.1.15.56）发现**已经不需要补丁了**：

| 启动器 | 结果 |
|---|---|
| 官方 4.1.15.56 启动器，**原样** | ✅ 正常拉起独立实例 |
| 打了旧版补丁的 4.1.15.56 启动器 | ❌ 启动即退出 |

原因是新版微信的单实例判定，已经改为**基于用户目录**（每个用户目录算一个独立用户），
而不是全局进程检查。只要把 `USERPROFILE` 指到不同目录，新版微信就认为
「这是一个新用户」，直接放行。

所以现在的做法是：**不碰二进制**，靠环境隔离。

> 旧版微信（4.1.15 之前）是否仍需补丁，取决于该版本的具体实现。
> 本工具面向当前主流的 4.x 版本，检测到不兼容时会明确报错，而不是默默失败。

### 隔离是怎么做到的

```
启动器（每个实例一个 .bat）
    ├─ set USERPROFILE=<实例>\Profile
    ├─ set APPDATA=<实例>\Profile\AppData\Roaming
    ├─ set LOCALAPPDATA=<实例>\Profile\AppData\Local
    ├─ set TEMP / TMP=<实例>\Profile\AppData\Local\Temp
    ├─ 防重复启动检查（在跑就直接退出）
    └─ start <实例>\Weixin.exe
```

同时在 `<实例>\Profile\AppData\Roaming\Tencent\xwechat\config\51a1fffe…ini`
里写一行绝对路径，告诉微信「你的聊天数据根在 `<安装目录>\Data\<代号>`」。

### 为什么必须用独立安装目录

微信启动器**只认自己所在目录下的版本库目录**（形如 `4.1.15.56`），
所以每个实例都要有一份完整的程序文件副本。这也是每个实例占约 870 MB 的原因。

⚠️ **版本库目录必须真复制，不能用硬链接** —— 微信更新时会就地改写文件，
硬链接会让所有实例一起被改坏。

## 技术架构

```
wechatmulti/
├── core.py       核心：实例模型、目录规划、启动脚本生成、进程归属判定
├── finder.py     自动定位本机已安装的官方微信（注册表 → 常见目录）
├── installer.py  安装器：选目录、复制程序文件、铺工具
├── gui.py        管家界面：实例列表、工具箱、引导
├── guard.py      防重复启动：读进程 PEB 里的 USERPROFILE 判定实例归属
├── tagger.py     窗口打标
└── patcher.py    旧版二进制补丁器（保留供参考，新版已不需要）
```

**进程归属判定**是整套东西的技术核心。微信 4.x 是 Qt 自绘 UI，
UIAutomation 完全失效（主窗口的 UIA 子节点数为 0），没法用常规办法
区分「这个微信窗口属于哪个实例」。

解法是读**进程 PEB 里的 `USERPROFILE` 环境变量**：

```
PEB.ProcessParameters              = 0x20
RTL_USER_PROCESS_PARAMETERS.Environment = 0x80
```

每个实例的 `USERPROFILE` 都不一样，所以「这个进程属于哪个实例」
一问 PEB 就知道，100% 准确，不依赖窗口标题这种能被改的东西。

## 常见问题

**Q：需要管理员权限吗？**
装到 `C:\Program Files` 下需要，普通目录不需要。

**Q：会封号吗？**
本工具不修改微信行为，只是多开几个自己的账号。腾讯的封号政策针对的是
自动化、群控、营销等行为，与「同机多账号」无关。请自行遵守微信用户协议。

**Q：几个号能同时在线？**
受电脑性能限制。每个实例约占用 1–2 GB 内存，建议不超过 3 个。

**Q：换了新电脑怎么办？**
把整个安装目录的 `Data\<代号>\` 拷过去，在新电脑上重新加实例并指定同样的数据根。

**Q：官方更新微信后还能用吗？**
能。本工具不自带微信文件，每次启动都用你本机当前版本。
若微信做了不兼容改动，工具会明确报错。

**Q：为什么我的实例启动后没反应？**
见 [docs/常见问题.md](docs/常见问题.md)。

## 已知限制

- 只支持 Windows 10 / 11
- 针对微信 **4.x**（4.1.15 及以后实测通过）
- 每个实例占约 870 MB 程序文件 + 聊天数据
- 不支持 3.x 及更早版本（UI 结构不同）
- 微信 4.x 是自绘 UI，无法用 UI 自动化操作，首次登录需手动扫码
