# 发布前检查清单

> 目的：**发出去的包和仓库里，不能带着任何本机特有的东西**。
> 本项目不像代理工具那样带订阅地址，但仍有三类东西要查：
> 本机绝对路径、个人信息、腾讯的文件。

---

## 一、本项目要查什么

| 类别 | 具体是什么 | 为什么要查 |
|---|---|---|
| **本机绝对路径** | `D:\WorkBuddyData\...`、`C:\Users\peter\...` | 暴露用户目录结构，且让脚本在别人机器上跑不起来 |
| **个人信息** | 用户名、wxid、邮箱、真实数据根路径 | 隐私 |
| **腾讯的文件** | `Weixin.exe`、`Weixin.dll` | **不能分发** —— 仓库和安装包里都不许有 |
| **运行数据** | `instances.json`、`guide_state.json` | 含本机绝对路径 |

## 二、逐条执行

### 1. 仓库里没有腾讯的文件

```bat
git ls-files | findstr /I "Weixin Weixin.dll xwechat ilink"
```

**期望：没有任何输出。**

特别检查别把 `D:\WeChatMulti\` 里的东西复制进仓库。

### 2. 没有本机绝对路径

```bat
:: 仓库里搜本机路径
git grep -n -I -E "D:\\\\WorkBuddyData|C:\\\\Users\\\\peter|WeChatMulti\\\\[ABC]"

:: 期望：只有 docs/ 里讲原理的示例（那些是说明性文字，不是真实路径）
```

如果有命中，看清楚是不是「举例说明」。是的话可以保留，但要确认**不含真实 wxid 或用户名**。

### 3. 没有个人信息

```bat
git grep -n -I -i -E "peter|phoenixonworld|cyberironman|wxid_[0-9a-z]+|andheart|@[a-z]+\.(com|cn|qq)"

:: 期望：只有 LICENSE 里的版权署名、README 里的作者署名
```

**特别检查 `instances.json`** —— 里面有绝对路径的数据根，绝不能进仓库。

### 4. 运行数据没进仓库

```bat
git ls-files | findstr /I "instances.json guide_state.json .log .lnk .bat"

:: 期望：.bat 只有 docs/ 里的示例（如果有），instances.json 必须是空的
```

`.gitignore` 里已经挡了 `/Data/`、`/data/`、`/logs/`、`/runtime/`、
`/_*.py`、`/_*.txt`、`/_*.png`。注意**必须带开头的斜杠**，
否则会把 `wechatmulti/` 里的东西一起忽略掉。

### 5. 沙箱残留已清理

```bat
dir /b _sandbox_* 2>nul
dir /b _*.py 2>nul
dir /b _*.txt 2>nul

:: 期望：都没有（或者只有 .gitignore 明确放行的）
```

沙箱目录里可能有**几 GB 的微信程序文件副本**，绝不能提交。

### 6. 版本号一致

```bat
type wechatmulti\__init__.py | findstr __version__
findstr "版本" README.md
findstr "^## v" CHANGELOG.md
```

三处版本号必须一致。

### 7. 测试全绿

```bat
python -m pytest tests\ -v
```

**期望：全部 PASSED。**

### 8. 打包产物正确

```bat
python scripts\build_exe.py
python scripts\build_release.py
```

检查：

- 4 个 exe 都在 `dist\`
- exe 的**时间戳是刚才**（不能是旧的缓存）
- zip 里**没有** `Weixin.exe` / `Weixin.dll`
- `.sha256` 与 zip 对得上

```bat
:: 确认 zip 里没有腾讯的文件
python -c "import zipfile;print([n for n in zipfile.ZipFile('dist\WeChatMulti-v0.1.0-win64.zip').namelist() if 'Weixin' in n or 'xwechat' in n])"
:: 期望：[] 
```

## 三、★ 实验安全红线

**这一条比上面所有都重要。**

2026-10-30 出过一次事故：某个对照实验脚本为了「清场」写了批量 kill 微信进程的逻辑，
结果把用户正在使用的**微信 A / B / C 三个实例全部杀掉了**。
数据一个没丢（重启即恢复），但这是不可接受的 —— 实验脚本绝不能碰用户的真实环境。

### 现在的硬约束

1. **所有实验只在 `_sandbox_*` 目录里跑** —— 路径必须带这个标记。
2. **`wechatmulti/sandbox.py` 的 `assert_sandbox()` 会拒绝任何非沙箱路径**，
   包括 `D:\WeChatMulti\B`、`C:\Program Files\Tencent\Weixin`、`E:\WEIXIN` 等真实位置。
3. **`sandbox` 模块里没有任何 kill 函数的对外接口** —— 只读，不杀。
   （有单元测试 `test_sandbox_module_has_no_kill_helper` 守着这条。）
4. 验证「实例能不能起来」的判据必须是
   **「有没有带沙箱 profile 的新进程」**，绝不能是「别人的进程还在不在」。

### 新写实验脚本时

```python
from wechatmulti import sandbox

sb = sandbox.sandbox_root("mytest")     # 路径带 _sandbox_ 标记
sandbox.assert_sandbox(sb)              # 非沙箱路径直接抛异常
bat = sandbox.spawn_instance(home, prof) # 唯一的启动入口
pids = sandbox.watch_sandbox_pids(prof, before)   # 只读
```

**先 import sandbox，不要自己写清场逻辑。**

### 另一个坑：退出码不能当判据

微信启动器的退出码 `-1` **无法区分**「崩溃」和「被单实例门挡住后干净退出」。
多实例场景下测「能不能启动」，必须看**实例自己的进程有没有冒出来**。
