# 常见问题

---

## 安装与启动

**Q：双击图标没反应？**

按顺序排查：

1. 打开「微信多开管家」看实例状态。如果显示「运行中」，那就是**防重复启动拦住了** ——
   实例已经在跑，直接切窗口过去就行。
2. 如果显示「未运行」但点了没反应，看有没有弹出的错误窗口。
3. 手动跑一下启动脚本看报错：`<安装目录>\<代号>\` 里的 `.bat`。
4. 检查目录是不是被 OneDrive 同步了 —— 微信写不进去。**换成非同步目录。**

**Q：安装器说「请把整个安装包文件夹一起复制」**

安装器需要同目录下的 `微信多开管家.exe` 才能工作。
不要只拷一个安装器 exe，把整个文件夹拷过去。

**Q：能不能装到 C 盘？**

能，但要注意两点：

- 装到 `C:\Program Files` 需要管理员权限
- 每个实例约 870 MB，3 个实例就是 2.6 GB，**别把系统盘塞满**

**Q：能不能装到 OneDrive / 网盘 / U 盘？**

**不能。**

| 位置 | 问题 |
|---|---|
| OneDrive 等同步盘 | 同步会锁文件，微信写不进去；聊天记录还会被同步到云端 |
| 网络盘 | 微信持续读写，网络延迟会让它卡死 |
| U 盘 / 移动硬盘 | 拔出来就没了，微信也会崩 |

## 多开与登录

**Q：扫码后提示「该账号已在其它设备登录」？**

微信自己的策略 —— 同一个账号不能同时登两台设备。
把另一台设备上的那个号退出，或用不同账号。

**Q：第二个实例一直卡在登录界面？**

多半是**配置串了**。检查启动脚本里五个环境变量是不是都设了：

```
USERPROFILE / APPDATA / LOCALAPPDATA / TEMP / TMP
```

少一个就可能互相踢。

**Q：能开几个？**

受内存限制。每个实例约 1–2 GB 内存，**建议不超过 3 个**。

**Q：官方更新微信后，多开的实例还是旧版本？**

会。微信的自动更新只作用于**主实例**（装在 `Program Files` 里的那个）。
多开实例用的是自己的副本，官方不会去更新它。

**同步方法**：删掉旧实例 → 重新新增 → 手动把聊天记录拷回去。
或者直接把主实例的版本库目录复制过去覆盖。

## 数据与备份

**Q：聊天记录存在哪？**

```
<安装目录>\Data\<代号>\xwechat_files\
```

**和程序文件是分开的** —— 删实例不会连聊天记录一起删（除非你显式勾选删除）。

**Q：怎么备份？**

直接复制 `Data\<代号>\` 整个目录。恢复时在新电脑上新增实例，
然后手动把数据根指到拷回来的目录。

**Q：换电脑怎么迁移？**

1. 新电脑装官方微信 + 本工具
2. 把旧电脑的 `Data\<代号>\` 拷过去
3. 新增实例，手动指定数据根指向拷回来的目录
4. 扫码登录（聊天记录会回来，但**登录状态要重新扫**）

**Q：删除实例会删掉聊天记录吗？**

默认**不删**。管家会明确问你。
想彻底清干净就手动去删 `Data\<代号>\`。

## 合规与安全

**Q：这算破解吗？**

不算。本项目**完全使用原版微信客户端，不改任何二进制文件**。
做的只是给每个实例设不同的 `USERPROFILE` 和数据根 ——
这是环境变量层面的配置，任何程序都可以这么做。

腾讯官方本身就允许多开，本项目只是让这件事更方便。

**Q：会上传我的数据吗？**

**完全不会。** 全程离线运行：

- 不联网
- 不写注册表
- 不装驱动、不装服务、不设开机启动
- 不改系统代理、不改 hosts

代码全在仓库里，欢迎逐行审阅。

**Q：会不会被封号？**

本工具不修改微信行为、不做自动化、不群控。
腾讯的封号政策针对的是自动化、营销、群控等行为，
与「同机多账号」无关。请自行遵守微信用户协议。

**Q：仓库里为什么没有微信文件？**

因为**不能分发腾讯的文件**。本工具在安装时自动读取你本机已装的微信版本，
复制一份到你选的目录。所以：

- 仓库只有几十 MB（而不是把官方目录镜像进来的 921 MB）
- 官方更新微信后本工具照常可用，不用等我们发新版

## 开发相关

**Q：怎么跑测试？**

```bat
pip install -r requirements-dev.txt
python -m pytest tests/ -v
```

测试全部在临时目录里跑，**不碰你真实的微信实例**。

**Q：能不能在开发时做实验？**

能，但**必须用沙箱**：

```python
from wechatmulti import sandbox

sb = sandbox.sandbox_root("mytest")     # 路径带 _sandbox_ 标记
sandbox.assert_sandbox(sb)              # 非沙箱路径会抛异常
```

`sandbox` 模块**不提供 kill 能力**，只读不杀。
需要判断「实例起没起来」，用 `sandbox.watch_sandbox_pids(prof, before)`。

⚠️ **不要自己写清场逻辑去 kill 别的微信进程。**
2026-10-30 出过一次事故：某个实验脚本为了「清场」批量 kill 微信进程，
把用户正在用的三个实例全杀了（数据没丢，重启即恢复，但不该发生）。
现在 `sandbox.py` 就是为了防止再犯。

**Q：为什么代码里还有个 `patcher.py`，README 说不用补丁？**

那是**历史模块**，已停用（`patcher.NEEDED = False`）。
留着是为了记录早期方案、并给将来的旧版微信留个后路。
